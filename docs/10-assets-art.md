# 10. 에셋과 아트

> 상태: 🟡 부분 (핵심은 적용 완료, 적·보스 외형이 임시) · 마지막 코드 대조 2026-09-01

## 한 줄 요약

플레이어·상인·HUD·음악은 실제 에셋이 들어가 있고, **적과 보스의 겉모습은 아직
코드로 찍은 임시 도트**입니다. 그림은 대부분 `AssetFactory`가 실행 중에 만들어 냅니다.

## 픽셀 아트 제작 기준

| 용도               | 제작 크기            |
| ------------------ | -------------------- |
| 기준 해상도        | 480 × 272            |
| 기본 타일          | 16 × 16              |
| 열쇠·폭탄·코인 HUD | 16 × 16              |
| 수집 아이템        | 32 × 32              |
| 플레이어 · 일반 적 | 약 32 × 32           |
| 큰 적              | 48 × 48 또는 64 × 64 |
| 보스               | 64 × 64 ~ 96 × 96    |

**가장 가까운 픽셀 방식으로 확대하고 안티앨리어싱을 쓰지 않습니다.**

## 그림이 만들어지는 두 가지 경로

이 프로젝트의 그림은 두 방식이 섞여 있습니다.

| 방식                 | 무엇                                                   | 어디에                            |
| -------------------- | ------------------------------------------------------ | --------------------------------- |
| **PNG 파일**         | 플레이어, 상인, HUD 아이콘, 상자, 스크롤, 음악         | `public/assets/`                  |
| **코드로 찍는 도트** | 적, 보스, 바닥, 벽, 문, 아이템 아이콘 32종, 폭탄, 텃밭 | `src/systems/*PixelSprites.ts` 등 |

코드로 찍는 도트는 **격자 문자열 + 색 팔레트**로 그립니다. 문자 하나가 픽셀 하나입니다.
공용 함수 `drawPixelGrid`가 이를 텍스처로 만들어 줍니다.

> **팔레트에 없는 글자가 나오면 조용히 비우지 않고 오류를 던집니다.**
> 그림에 구멍이 뚫린 채로 지나가는 것을 막기 위해서입니다.

## 도트 그림을 만들 때 지킬 것

1. **구현한 뒤 반드시 PNG로 렌더링해 눈으로 확인합니다.**
   (스크래치 패드에 렌더 스크립트 패턴이 있습니다)
2. **격자 문자열은 행 길이와 좌우 대칭을 프로그램으로 검사합니다.**
   한 줄만 튀어도 원이 계란으로 보입니다 — 폭탄 몸통을 5-9-11-11-13(×5)-11-11-9-5로
   맞춘 것이 그 예입니다
3. **표시 크기를 줄일 때는 충돌 범위를 따로 지정합니다.** 정적 바디는 `setScale`을
   따라가지 않아서, 그냥 두면 그림보다 판정이 커집니다 (상자에서 실제로 있었던 버그)
4. **곱셈 tint는 어두운 색에 거의 안 먹힙니다.** 검은 폭탄 몸통은 tint에 반응하지
   않아서, 임박함을 밝은 불꽃·광택으로만 알립니다
5. **형제 관계인 그림은 같은 격자·같은 규격으로 찍고 한 가지만 다르게 합니다.**
   일반 굴과 8층 탈출구는 같은 16×10 격자에 **빛의 방향만** 다릅니다
