# 10. 에셋과 아트

> 상태: 🟡 부분 (핵심은 적용 완료, 적·보스 외형이 임시) · 마지막 코드 대조 2026-09-01

## 한 줄 요약

플레이어·상인·HUD·음악은 실제 에셋이 들어가 있고, **적과 보스의 겉모습은 아직
코드로 찍은 임시 도트**입니다. 그림은 대부분 `AssetFactory`가 실행 중에 만들어 냅니다.

## 픽셀 아트 제작 기준

### 동굴 그래픽 기준 화면 (2026-10-24)

`CaveArt.ts`는 1층의 모든 방에 불규칙한 흙벽, 자갈, 갈라진 뿌리가 있는 땅굴을 생성한다.
2층의 모든 방에는 벽돌, 묻힌 석판과 오래된 각인이 있는 유적을 적용한다.
방마다 고정된 그레인과 지형 변화를 가지며, 출입구는 실제 방의 출구 방향을 따른다.
3층은 젖은 점토와 웅덩이, 4층은 지렁이 굴 흔적과 알집, 5층은 버섯과 썩은 식물,
6층은 퇴비·벽돌·녹슨 농기구, 7층은 넝쿨과 틈새 햇빛, 8층은 목재 지지대가 있는
농장 지하실이다. `CaveThemes.ts`가 8개 층의 재질 색, 주변광, 안개와 광원 색을 관리한다.

`CaveAtmosphere.ts`는 횃불 2개, 층별 발광 지점, 낮은 농도의 안개와
먼지 32개를 표시한다. 프리즘 창·폭탄·적 탄환·잔불이 주변 바닥과 벽을 비춘다.
배경과 공기 효과는 탄환·캐릭터·공격 예고보다 아래에 표시되며, HUD에는 적용하지 않는다.
입자 배치는 전투 난수와 분리되어 있고, 임시 조명은 최대 12개로 제한된다.

`PixelFire.ts`는 횃불의 부력·공기 저항·휘어 오르는 흐름과 불티의 중력을 계산한다.
불꽃은 밝은 노랑에서 주황·붉은색으로 식으며 사라지고, 연기와 작은 불티가 분리된다.
폭탄은 주변 입자를 밀어내고 방사형 불티를 방출한다. 폭발 자리의 불씨는 바닥에 가라앉아
4~~7초 동안 작은 불꽃과 연기를 내며 식는다. 불씨는 최대 96개, 공중 입자는 최대 420개이며
고정 시간 간격으로 계산한다. 방을 바꾸면 이전 방의 불꽃은 초기화된다.
폭탄 껍질·철·탄 도화선 조각은 5~~8초간 남으며, 일부는 기존 방별 잔해에 저장된다.

`CaveLighting.ts`는 배경의 재질 명암을 평활화한 뒤 법선맵을 추정한다.
`CaveIllumination.ts`가 WebGL의 Light2D로 배경 요철을 비추고, 불꽃·마법만 별도
120×68 발광 버퍼에 모아 분리형 가우시안 블러를 적용한다. 도트 원본과 HUD는 흐리지 않는다.
블룸은 불꽃보다 뒤에 45% 강도로 표시하며, 텍스처를 갱신할 때마다 선형 보간을 다시 적용해
확대된 사각 픽셀이 횃불을 가리지 않도록 한다. 불꽃·잔불 주변의 별도 사각형 후광은 그리지 않는다.
이는 배경 표면 조명이며, 문·상자·캐릭터의 법선맵 및 벽 뒤로 드리우는 그림자는 포함하지 않는다.

| 그래픽 품질 | 동시 표면 광원    | 블룸 갱신      |
| ----------- | ----------------- | -------------- |
| 낮음        | 0, 기존 색광 사용 | 끔             |
| 균형        | 최대 6개          | 초당 최대 15회 |
| 높음        | 최대 10개         | 초당 최대 30회 |

Canvas 렌더러에서는 기존 색광으로 동작한다. 광원 객체 10개를 재사용하고 화면 밖 광원은 제외하며,
폭발·빔을 우선 선택한다. 밀집한 탄환은 48픽셀 구역당 대표 하나, 잔불은 폭발 위치당 하나로 묶는다.
최근 6개 방의 배경·법선 데이터를 캐시하며 GPU에는 현재 방 한 세트만 유지한다.
흙벽 요철은 각 흙덩이 주변만 미리 계산하여 방 생성 시 반복 거리 계산을 줄였다.

2026-10-24 검증: 8개 테마를 WebGL에서 렌더링하고 연속 폭발 30회를 실행했다.
방 전환 후에도 법선 데이터 소스 1개·광원 풀 10개·캐시 최대 6개를 유지했고,
균형 품질의 활성 광원은 6개 이하였다. 자동 검사 771개와 빌드가 통과했다.
테스트 브라우저는 소프트웨어 WebGL이므로 실제 기기의 전투 FPS 측정은 별도로 진행한다.

문·나무 상자·보물상자는 `propPixelSprites.ts`에서 1픽셀 단위로 생성한다.
저채도의 목재, 끊어진 나뭇결, 녹슨 철띠, 낡은 황동과 작은 못을 같은 재질 팔레트로 표현한다.
문은 48×16(세로문은 전치), 나무 상자는 40×40, 보물상자는 열림·닫힘 모두 64×64로
기존 표시 크기와 충돌 범위를 유지한다. 나무 상자의 피격 파임과 파편은 새 텍스처 색을 사용한다.
기존 보물상자 PNG는 보관하되 로딩하지 않고, 열린 모습도 같은 코드 도트로 생성한다.

| 용도               | 제작 크기            |
| ------------------ | -------------------- |
| 기준 해상도        | 480 × 272            |
| 기본 타일          | 16 × 16              |
| 열쇠·폭탄·코인 HUD | 16 × 16              |
| 수집 아이템        | 32 × 32              |
| 플레이어 · 일반 적 | 약 32 × 32           |
| 큰 적              | 48 × 48 또는 64 × 64 |
| 보스               | 64 × 64 ~ 96 × 96    |

**가장 가까운 픽셀 방식으로 확대하고 안티앨리어싱을 쓰지 않습니다.**

## 그림이 만들어지는 두 가지 경로

이 프로젝트의 그림은 두 방식이 섞여 있습니다.

| 방식                 | 무엇                                                         | 어디에                            |
| -------------------- | ------------------------------------------------------------ | --------------------------------- |
| **PNG 파일**         | 플레이어, 상인, HUD 아이콘, 스크롤, 음악                     | `public/assets/`                  |
| **코드로 찍는 도트** | 적, 보스, 바닥, 벽, 문, 상자, 아이템 아이콘 32종, 폭탄, 텃밭 | `src/systems/*PixelSprites.ts` 등 |

코드로 찍는 도트는 **격자 문자열 + 색 팔레트**, 또는 직접 생성한 픽셀 데이터로 그립니다.
격자 방식은 문자 하나가 픽셀 하나이며, 공용 함수 `drawPixelGrid`가 이를 텍스처로 만들어 줍니다.

> **팔레트에 없는 글자가 나오면 조용히 비우지 않고 오류를 던집니다.**
> 그림에 구멍이 뚫린 채로 지나가는 것을 막기 위해서입니다.

## 도트 그림을 만들 때 지킬 것

1. **구현한 뒤 반드시 PNG로 렌더링해 눈으로 확인합니다.**
   (스크래치 패드에 렌더 스크립트 패턴이 있습니다)
2. **격자 문자열은 행 길이와 좌우 대칭을 프로그램으로 검사합니다.**
   한 줄만 튀어도 원이 계란으로 보입니다 — 폭탄 몸통을 5-9-11-11-13(×5)-11-11-9-5로
   맞춘 것이 그 예입니다
3. **표시 크기를 줄일 때는 충돌 범위를 따로 지정합니다.** 정적 바디는 `setScale`을
   따라가지 않아서, 그냥 두면 그림보다 판정이 커집니다 (상자에서 실제로 있었던 버그)
4. **곱셈 tint는 어두운 색에 거의 안 먹힙니다.** 검은 폭탄 몸통은 tint에 반응하지
   않아서, 임박함을 밝은 불꽃·광택으로만 알립니다
5. **형제 관계인 그림은 같은 격자·같은 규격으로 찍고 한 가지만 다르게 합니다.**
   일반 굴과 8층 탈출구는 같은 16×10 격자에 **빛의 방향만** 다릅니다
