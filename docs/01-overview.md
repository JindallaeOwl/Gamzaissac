# 01. 게임 개요와 개발 환경

> 상태: ✅ 안정 · 마지막 코드 대조 2026-09-01

## 어떤 게임인가

**GAMZAISSAC(감자이삭)** — 웹 브라우저에서 도는 2D 탑다운 로그라이크 액션 게임입니다.

- **이야기**: 땅속 깊은 곳에서 깨어난 감자가 위로 파고 올라가 농장을 탈출한다. 가볍고 유쾌한 톤
- **한 판(런)의 흐름**: 방 하나씩 클리어하며 아이템을 모으고, 각 층 끝의 보스를 잡아
  위층으로 올라간다. 8층 최종 보스를 잡으면 탈출 성공, 체력이 다 하면 게임오버
- **장르 참고**: 아이작(The Binding of Isaac) 계열 구조를 의도적으로 학습 대상으로 삼되,
  특정 게임의 캐릭터·아이템·아트·명칭을 직접 복제하지 않습니다

## 기술 스택

| 무엇      | 무엇을 쓰나       | 버전       | 왜                             |
| --------- | ----------------- | ---------- | ------------------------------ |
| 게임 엔진 | Phaser 3          | ^3.80.1    | 2D 웹 게임용, Arcade 물리 사용 |
| 언어      | TypeScript        | ^5.4.5     | 타입 검사로 실수를 미리 잡음   |
| 빌드 도구 | Vite              | ^8.1.3     | 개발 서버가 빠름               |
| 테스트    | Vitest            | ^4.1.10    | 규칙 함수의 자동 검사          |
| 코드 검사 | ESLint + Prettier | ^10 / ^3.2 | 문법 실수·형식 통일            |

**의존성이 Phaser 하나뿐**입니다. 게임 로직·UI·도트 그림 생성 모두 직접 만든 코드입니다.

## 화면 규격

| 항목             | 값                                                       |
| ---------------- | -------------------------------------------------------- |
| 논리 해상도      | 480 × 272                                                |
| 기본 격자        | 16 × 16 픽셀                                             |
| 방 안쪽 영역     | 416 × 208 (좌 32, 상 32에서 시작)                        |
| 벽 두께          | 16                                                       |
| 확대 방식        | 가장 가까운 픽셀(nearest) — 안티앨리어싱 없음            |
| 렌더 품질 기본값 | 높음(4배). 설정에서 낮음(1배)·균형(2배)로 즉시 변경 가능 |

창 비율이 게임과 다르면 위아래 또는 좌우에 여백이 생기고, **게임 전체가 잘리지 않고
항상 보입니다.** (`tests/render-scale.test.ts`가 이 규칙을 지킵니다.)

## 실행 방법

```bash
npm install
npm run dev     # http://127.0.0.1:5173
```

## 검사 방법 (기능을 고친 뒤 반드시)

```bash
npm run check
```

`check`는 아래 다섯 가지를 순서대로 돌립니다.

1. ESLint (문법·코드 규칙)
2. Vitest (단위 테스트 557개)
3. Prettier (코드 형식)
4. TypeScript 타입 검사
5. Vite 프로덕션 빌드

테스트만 반복해서 보고 싶을 때는 `npm run test:watch`를 씁니다.

> **알려진 함정**: `npm run check`가 가끔 모든 테스트 파일을 `reading 'config'` 오류로
> 실패시킵니다. **다시 실행하면 통과합니다.** 진짜 고장으로 오해하지 마세요.

> 빌드에서 나오는 "500kB 이상 번들" 경고는 빌드를 실패시키지 않는 안내입니다.
> 코드 분할 최적화는 v1.0 이후 작업입니다.

## 폴더 구조

```text
src/
  config/     화면 크기, 전투 수치, 피드백 값, 에셋 키       ← 숫자를 고칠 곳
  data/       아이템·적·보상·방 템플릿·상점·스테이지 데이터  ← 콘텐츠를 늘릴 곳
  entities/   플레이어, 적, 탄환, 빔, 문, 폭탄, 픽업          ← 화면에 있는 물체
  i18n/       한국어/영어 번역
  scenes/     Boot / Title / TitleTransition / Game / Pause   ← 화면 단위
  systems/    던전·방·아이템·보상·전투·오디오·개발자도구 로직 ← 규칙이 사는 곳
  ui/         HUD, 미니맵, 보스 체력바, 설정, 개발자 콘솔
  utils/      방향·수학·랜덤 같은 작은 도구들
tests/        systems·utils의 규칙 함수 단위 테스트
public/       실제 이미지·음악·폰트 파일
```

### 코드를 나눈 기준 (중요)

이 프로젝트는 **"판단하는 규칙"과 "화면에 그리는 코드"를 일부러 떼어 놓습니다.**

- `systems/`의 `~Rules.ts` 파일들은 **순수 함수**입니다 — 입력을 주면 항상 같은 답이
  나오고, Phaser를 모릅니다. 그래서 테스트로 고정할 수 있습니다
- `entities/`와 `scenes/`는 그 답을 받아 화면에 반영만 합니다

새 규칙을 만들 때 이 형태를 지키면 자동 테스트를 붙일 수 있고, 나중에 "왜 이렇게
동작하지?"를 코드 한 곳만 보면 알 수 있게 됩니다.
